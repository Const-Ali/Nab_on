# سامانه ناب | مدیریت پرونده‌های سازمانی

اپلیکیشن فارسی و راست‌چین برای مدیریت پرونده‌ها، گردش‌کار، کاربران، گزارش‌ها و کارها. نسخهٔ استقرار فعلی برای **هاست اشتراکی PHP + MySQL/MariaDB** آماده شده است؛ داده‌های عملیاتی به‌صورت JSON در جدول‌های دیتابیس هاست ذخیره می‌شوند و ورود، نشست و مجوزها در سمت سرور کنترل می‌شوند.

> این نسخه حساب دمو یا رمز پیش‌فرض ندارد. برای استفادهٔ واقعی، ابتدا روی هاست راه‌اندازی کنید و مدیر اولیه را خودتان بسازید.

## پیش‌نیازهای هاست

- PHP 8.1 یا جدیدتر، با PDO و درایور `pdo_mysql`
- MySQL 5.7+ یا MariaDB 10.3+
- Apache با PHP و `mod_rewrite` فعال (یا معادل تنظیمات Rewrite در هاست)
- گواهی HTTPS فعال؛ کوکی نشست امن در محیط واقعی به HTTPS نیاز دارد
- دسترسی برای ساخت دیتابیس و واردکردن `database/schema.sql`

## استقرار روی هاست اشتراکی

1. در cPanel یا پنل هاست، یک دیتابیس MySQL و کاربر بسازید و دسترسی کامل کاربر را به همان دیتابیس بدهید.
2. فایل `database/schema.sql` را یک‌بار با phpMyAdmin یا ابزار دیتابیس هاست وارد کنید.
3. روی دستگاه خود، در ریشهٔ پروژه اجرا کنید:

   ```bash
   npm ci
   npm run build
   ```

4. **محتویات پوشهٔ `dist/`** (نه خود پوشه) را در document root سایت، معمولاً `public_html/`، بارگذاری کنید. فایل‌های مخفی مانند `.htaccess` را هم بارگذاری کنید. `api.php` باید در همان document root و کنار `index.html` باشد.
5. فایل `nab-config.example.php` را بیرون از document root کپی و با نام `nab-config.php` ذخیره کنید. در پیکربندی واقعی، مقادیر دیتابیس و یک `setup_key` تصادفی و طولانی را جایگزین کنید. برای مثال، کلید تصادفی را روی دستگاه خود با `openssl rand -hex 32` بسازید. **رمز دیتابیس و کلید راه‌اندازی را در گفتگو، داخل کد فرانت‌اند یا در پوشهٔ عمومی سایت قرار ندهید.**
6. در چیدمان متداول cPanel، اگر document root برابر `/home/ACCOUNT/public_html` باشد، فایل تنظیمات باید در `/home/ACCOUNT/nab-config.php` باشد؛ مسیر را با مسیر واقعی `public_html` تطبیق دهید. در صورت امکان دسترسی فایل تنظیمات را به مالک محدود کنید.
7. HTTPS را فعال کنید و سپس سایت را باز کنید. در نصب تازه، فرم یک‌بارهٔ ساخت مدیر نمایش داده می‌شود؛ `setup_key` را از فایل خصوصی پیکربندی وارد کنید. رمز مدیر باید حداقل ۱۲ نویسه باشد.
8. پس از ورود مدیر، کاربران را دوباره از داخل برنامه ایجاد کنید. **هیچ نام کاربری/رمز دمو یا پیش‌فرضی در این نسخه وجود ندارد.**

فایل `public/.htaccess` در build به `dist/.htaccess` کپی می‌شود. این فایل فهرست‌نمایی را می‌بندد، فایل‌های خصوصیِ اشتباهی را مسدود می‌کند و مسیر SPA را به `index.html` برمی‌گرداند. اگر میزبان `mod_rewrite` یا دستورهای `.htaccess` را محدود کرده است، از پشتیبانی هاست بخواهید معادل همین قواعد را در Apache تنظیم کند؛ `.htaccess` نامعتبر می‌تواند خطای 500 ایجاد کند.

## انتقال داده‌های قدیمی مرورگر

پس از ورود مدیر، اگر داده‌های نسخهٔ قبلی در `localStorage` همان مرورگر و همان مبدأ سایت باقی مانده باشند، برنامه شمارش داده‌ها را نشان می‌دهد. مدیر می‌تواند:

- **دانلود پشتیبان** را انتخاب کند؛ فایل پشتیبان شامل داده‌های پرونده، رویدادها، یادداشت‌ها، نقش‌ها و کارهای قابل انتقال است.
- با دکمهٔ **انتقال داده‌ها به هاست** پرونده‌ها، رویدادها، یادداشت‌ها، نقش‌ها و کارهای شخصی همان مدیر را به دیتابیس بفرستد. انتقال داده‌های مشترک فقط برای مدیر و فقط به نصب تازه و خالی مجاز است؛ انتقال در یک تراکنش انجام می‌شود.
- پس از ساخت دوبارهٔ کاربران قدیمی، هر کاربر می‌تواند در مرورگر/حساب خودش فقط کارهای شخصی همان حساب را جداگانه منتقل کند؛ این کار داده‌های مشترک یا حساب‌های دیگر را تغییر نمی‌دهد.
- پس از گرفتن پشتیبان یا تصمیم آگاهانه، داده‌های قدیمی همین مرورگر را پاک کند.

حساب‌های قدیمی و رمزهای ذخیره‌شده در مرورگر عمداً منتقل نمی‌شوند. کاربران باید روی هاست دوباره ساخته شوند و رمز جدید بگیرند. داده‌های مرورگر روی دستگاه دیگری در دسترس این برنامه نیست؛ بنابراین با همان مرورگر و hostname قدیمی وارد شوید و قبل از پایان انتقال، پاک‌کردن دادهٔ سایت یا تغییر hostname انجام ندهید. اگر انتقال شکست بخورد، دادهٔ محلی پاک نمی‌شود؛ ابتدا پشتیبان بگیرید و علت پاسخ API/اعتبار داده را بررسی کنید.

## امنیت و پشتیبان‌گیری

- اطلاعات پرونده و کارها در دیتابیس هاست می‌ماند؛ فقط ترجیح‌هایی مانند تم و نوار کناری در مرورگر نگهداری می‌شوند.
- رمزها با `password_hash` ذخیره می‌شوند؛ رمز خام حساب‌ها به API بازگردانده نمی‌شود.
- endpointها نشست و CSRF را بررسی می‌کنند؛ دسترسی به پرونده، کاربر و یادداشت براساس مجوز سمت سرور محدود است.
- داده‌ها شامل اطلاعات حساس‌اند. از دیتابیس به‌صورت منظم نسخهٔ پشتیبان رمزگذاری‌شده بگیرید، دسترسی phpMyAdmin را محدود کنید و نسخهٔ پشتیبان را در محل عمومی سایت قرار ندهید.
- پوشهٔ `database/`، سورس پروژه و فایل واقعی `nab-config.php` را در document root بارگذاری نکنید. فقط خروجی `dist/` را منتشر کنید.
- API درخواست‌های JSON بزرگ‌تر از ۱۰ مگابایت را رد می‌کند. برای انتقال بسیار حجیم، داده را پیش از مهاجرت بازبینی کنید.

## توسعه و اجرای محلی با PHP و دیتابیس واقعی

دکمهٔ Run یا `npm run dev` در VS Code فقط رابط کاربری Vite را بالا می‌آورد؛ PHP و MySQL/MariaDB سرویس‌های جداگانه‌اند و باید خودتان اجراشان کنید. برای اجرای کامل برنامه در دستگاه محلی:

1. PHP 8.1+ با افزونهٔ `pdo_mysql` و یک سرور MySQL/MariaDB لازم است. برای شروع روی Windows می‌توانید از XAMPP استفاده کنید؛ در Control Panel سرویس **MySQL** را Start کنید.
2. در phpMyAdmin یک دیتابیس محلی بسازید (مثلاً `nab`)، آن را انتخاب و یک‌بار `database/schema.sql` را Import کنید.
3. در ریشهٔ پروژه `nab-config.example.php` را کپی و نسخهٔ کپی را `nab-config.php` بنامید. نام دیتابیس، کاربر و رمز **محلی** را وارد کنید و فقط برای HTTP محلی `secure_cookie` را `false` بگذارید. کلید `setup_key` باید تصادفی و دست‌کم ۳۲ نویسه باشد. فایل واقعی `nab-config.php` خصوصی است؛ آن را commit، بارگذاری یا برای کسی ارسال نکنید.
4. وابستگی‌های فرانت‌اند را فقط یک‌بار، از ریشهٔ پروژه، نصب کنید:

   ```bash
   npm ci
   ```

5. در ترمینال اول VS Code، از ریشهٔ پروژه، PHP را برای API اجرا کنید:

   ```bash
   php -S 127.0.0.1:8000 -t public
   ```

6. ترمینال دوم را باز کنید و Vite را اجرا کنید:

   ```bash
   npm run dev
   ```

   پروکسی توسعهٔ Vite درخواست‌های `/api.php` را به PHP روی پورت `8000` می‌فرستد؛ صفحه را با نشانی‌ای که Vite نشان می‌دهد (معمولاً `http://localhost:5173`) باز کنید. هر دو ترمینال و سرویس MySQL باید روشن بمانند.

در XAMPP ویندوز اگر `php` در ترمینال شناخته نشد، مسیر PHP را کامل بنویسید، مثلاً:

```powershell
C:\xampp\php\php.exe -S 127.0.0.1:8000 -t public
```

برای بررسی اتصال API می‌توانید `http://127.0.0.1:8000/api.php?action=status` را باز کنید. پاسخ `needs_setup: true` یعنی PHP و دیتابیس پاسخ می‌دهند و باید مدیر اولیه را بسازید. اگر پاسخ HTML/متن PHP یا پیام «مسیر /api.php باید توسط PHP اجرا شود» دیدید، درخواست هنوز به PHP نرسیده است؛ دو سرور و پروکسی Vite را بررسی کنید. اگر خطای اتصال دیتابیس گرفتید، نام دیتابیس/کاربر/رمز در فایل خصوصی را بررسی کنید.

برای خروجی نهایی از `npm run build` و برای کنترل کد از `npm run lint` استفاده کنید. در هاست واقعی، PHP و MySQL روی خود هاست اجرا می‌شوند؛ فایل خصوصی config را روی هاست بیرون از document root نگه دارید و `secure_cookie` را با HTTPS فعال، `true` بگذارید. اطلاعات اتصال واقعی را در محیط محلی و خارج از نسخهٔ کنترل‌شده نگه دارید.

## فناوری‌ها و ساختار

- React 19، TypeScript 6، Vite 8 و Tailwind CSS
- `src/App.tsx`: ورود، نشست، صفحات و همگام‌سازی داده‌ها
- `src/api-client.ts`: کلاینت same-origin برای `public/api.php`
- `public/api.php`: API نشست، کاربران، state و کارها
- `database/schema.sql`: ساختار MySQL/MariaDB
- `nab-config.example.php`: الگوی تنظیمات (بدون اطلاعات واقعی)
- `src/tasks/`: ماژول مدیریت کارها
